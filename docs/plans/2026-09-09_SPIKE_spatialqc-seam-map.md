## 5. GPU/CPU surface (for a `Backend` protocol)

### 5.1 The parity trap: the LoG operator is not the same on both paths

The CPU branch calls `scipy.ndimage.gaussian_laplace` — the analytic Laplacian-of-Gaussian kernel:

```python
# bin/image_qc.py:1230-1235 (CPU branch of compute_laplacian_variance_map)
    else:
        image_f = image.astype(np.float32, copy=False)
        if lap_sigma > 0:
            lap = scipy_gaussian_laplace(image_f, sigma=lap_sigma).astype(np.float64)
        else:
            lap = laplace_fn(image_f).astype(np.float64)
```

The GPU branch calls a locally defined shim that smooths first and then applies the _discrete_ Laplacian:

```python
# bin/image_qc.py:67-71
    def cupy_gaussian_laplace(image, sigma):  # type: ignore[misc]
        """CuPy Laplacian of Gaussian: Gaussian smooth then Laplacian."""
        from cupyx.scipy.ndimage import gaussian_filter as _gf

        return cupy_laplace(_gf(image, sigma=sigma))
```

`gaussian_laplace` and `laplace(gaussian_filter(...))` are **different discrete operators**, so the `lap_sigma > 0` path is **not numerically equivalent between CPU and GPU**.
The `lap_sigma == 0` path _is_ equivalent (both use the plain `laplace`: `scipy_laplace` at `bin/image_qc.py:46` vs `cupy_laplace` at `bin/image_qc.py:64`).

This is not confined to the small-image fallback.
The same `cupy_gaussian_laplace` shim is used by `_compute_channel_maps_on_gpu` at `bin/image_qc.py:1363` (with `cupy_laplace` at `:1365` for `lap_sigma == 0`), which is the **streaming / tiled path production actually runs** (`bin/image_qc.py:3454`, `3512`, `4059`).
`compute_laplacian_variance_map` is only the small-image / CPU fallback (`bin/image_qc.py:4120`, `5369`).
Consequence: the GPU-OOM fallback re-entry at `bin/image_qc.py:4103-4107` switches operators **mid-run**, so a run that spills off the GPU produces different Laplacian-variance numbers from one that does not.
A `Backend` protocol must either declare `gaussian_laplace` as a first-class primitive (and give the GPU side a real LoG), or document the discrepancy as accepted.
Contrast this with `snr_metrics.roi_snr_db_batch`, whose docstring explicitly claims exactness to ~1e-14 dB across devices (`bin/snr_metrics.py:279-282`) — the SNR path was designed for parity, the focus path was not.

2. **Reconcile Block B by hand** (section 1.2). Superset = `image_qc`'s version plus `extra=` plus `_frame_gb`. Decide the log sink explicitly; the transcript CLI configures no logging today.
3. Do **not** treat upstream `xenium_helpers.utils` as the source of truth for Block A or B — neither exists there (section 1.3). The four genuinely-upstream helpers (`calculate_noise_bound`, `estimate_min_mols_per_cell`, `format_yaml_like`, `dump_versions`) do match and can be re-sourced.
4. Promote `snr_metrics._HAS_NUMBA` to a public capability query before splitting (section 2.1).
5. Treat the QMD-consumed **filenames and JSON keys** as a frozen contract (section 3). The notebooks import zero project code, so nothing else about the Python layout is load-bearing for them.
6. Unify the four threshold loaders and eliminate `_EMBEDDED_THRESHOLDS_FALLBACK` (section 4); rename `ROI_THRESHOLDS_YAML` in the transcript QMD only with a matching Nextflow change.
7. Design the `Backend` protocol around the three dispatch styles and settle the `gaussian_laplace` parity question first (section 5.1).
8. Move `_WORKER`, `_DECODE_POOL`, `_DECODE_POOL_LOCK`, `_MEM_PEAK` deliberately — they are process/thread state, not configuration (section 6.1).
9. When relocating any name in section 7.3, update its `monkeypatch` target in the same commit. Re-export will pass CI while testing nothing.
10. Make `regionprops_table`, `nsitk`, `scanpy`, and `seaborn` function-local (section 8) — that alone removes every stub in `bin/tests/`, and it is specifically what makes deleting the four vestigial `scanpy` stubs safe.
